# FINDINGS/

One file per research track, populated during the Execution phase. The specific files here are defined in `PLAN.md` — this directory starts empty and grows as research is completed.

**Every findings file should:**
- Cite every factual claim with a URL (vendor sites, spec sheets, forum threads)
- Note when sources disagree — show the range, don't average
- Label forum and review summaries as opinion, not fact
- Flag anything that might shift the overall comparison in `OPEN_QUESTIONS.md`

**`cross-cutting.md` specifically should end with a summary filter table** — one row per key criterion, two columns (minimum acceptable / preferred). This table is derived from what the research surfaced and becomes the evaluation grid when assessing specific options in the other tracks. It also forces the cross-cutting research to land on something actionable rather than just informational.

**Suggested files (rename to match your tracks):**
- `cross-cutting.md` — foundational knowledge that applies to all options
- `[option-a].md` — research on the first path being compared
- `[option-b].md` — research on the second path
- `[option-c].md` — additional paths as needed
